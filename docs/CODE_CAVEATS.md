# 清单差异、输出单位与教程勘正

更新：2026-10-24。本页区分当前代码实际做什么、通常的物理定义是什么，以及尚未修改的历史行为。此次修订教程，未更改 Fortran 计算式或参考表。

## 1. 透平 SI 转速与派生输出

已直接查看 TN D-8063 印刷第 19 页（PDF 第 21 页）的清单。它与[现行源码的 SI 分支](../restored/turbine_tn_d8063.f#L341-L390)均有：

```fortran
      XNOTH=100.*U3/3.14159/D3/STHETA
      XN=XNOTH*STHETA
      TOR=DELH*W1*9.549274/XN
      P=DELH*W1/1000.
      XNS=XN*.10472*SCAPQ/(DHIDT**.75)
```

给定 `U3` 为 m/s、`D3` 为 cm，`100*U3/(pi*D3)` 是每秒转数。因此 `XN` 的数值是 rev/s；不是 rpm，也不是 rad/s。代码中的 `9.549274≈60/(2π)` 与 `.10472≈2π/60` 却是将 rpm 用于扭矩/角速度换算的系数。这种混用不会因浮点精度提高而消失。

| SI 输出字段 | 当前数值意义/问题 | 物理使用方式 |
| --- | --- | --- |
| `N`、`EQ-N`、`N/T` | 转速以 rev/s 为基础 | 需角速度时乘 `2π`；需 rpm 时乘 60 |
| `WN/DEL` | `w*N*EPS/DELTA`，其中 N 为 rev/s | 若采用角速度定义，也乘 `2π` |
| `TOR` | 约为通常物理扭矩数值的 60 倍 | 由独立的 `P_W/omega` 重算 |
| `EQ-TOR`、`TOR/P` | 继承 `TOR` 的尺度问题 | 用物理扭矩重新折合；`TOR/P` 中 P 指进口总压 |
| `NS`（长、短表都有） | 约为通常 SI 无量纲比转速的 1/60 | 用 `omega*sqrt(w/rho5)/DHIDT**0.75` 重算 |

此处的“约”包括历史常数和打印舍入，不能把除以或乘以 60 当作高精度计算的替代。美制分支使用另一组转换，不按本表直接修正。功率、效率等字段没有使用 `TOR` 或 `XNS` 反馈参与气动求解；这只说明该单位问题的依赖范围，不构成其他输出均正确的证明。

对[设计后继承系数示例](../restored/examples/turbine_design_then_offdesign.inp)的本次 modern64 实测，首个设计点打印：

```text
N       600.00       P       17.445
TOR     277.64       NS      0.97688E-02
W       0.33879      DEL-H   51492.
```

独立几何/功率换算为：

```python
from math import pi
D_m = 12.6238 / 100
omega = 2 * 237.9524 / D_m      # 3769.9012975 rad/s
rpm = 60 * omega / (2*pi)       # 35999.9055884 rpm
torque = 17445 / omega         # 4.6274421 N*m，使用已舍入的打印功率
```

如果要正式修改程序，应独立建立输出单位一致的候选版本，覆盖全部受影响字段并验证 SI/美制等效算例。当前保留清单值以便原表对照，**不能写成这些字段已经完成工程修正**。这也是“复现原表”不能替代物理量纲检查的具体例子。

## 2. 压气机无叶扩压器的积分终点

已直接查看 TN D-7487 印刷第 30 页（PDF 第 34 页）的清单；[现行源码](../restored/compressor_tn_d7487.f#L320-L382)保留：

```fortran
      R=1.0
      DELTAR=(VLDRR-1.)/10.
      DO 1000 NO=2,10
      ...
      R=R+DELTAR
```

循环含首尾，共 9 次推进，站点索引为 1 至 10；最后半径比为 `1+9*(VLDRR-1)/10`。例如 `VLDRR=1.14`，终点为 1.126。

报告正文的数值方法描述使用十个等距区间（印刷第 52 页，PDF 第 56 页），但清单循环边界如此。旧教程写“`NO=2,11`、10 步、已到达 VLDRR”与当前代码不符，现已纠正。这里记录文字与清单的差异，不声称 NASA 已正式确认勘误，也不自行把循环改到 11：那会改变损失及性能结果，须作为算法变化单独验证。
